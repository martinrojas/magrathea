## Structural changes

`DESIGN.md` now follows the Google DESIGN.md format (https://github.com/google-labs-code/design.md). Skip this note if the repo has no `DESIGN.md`. Keep filled-in content: move it, do not drop it.

- `DESIGN.md` front matter: set `version: alpha`, keep `name`, add an optional `description`. Remove `last_reviewed` and `owner`.
- `DESIGN.md` tokens: move the palette, type scale, radius and spacing values into YAML front matter groups `colors`, `typography`, `rounded`, `spacing`, and component styles into `components`. Use `{colors.primary}`-style references between tokens. List groups the product does not define under `omitted:`.
- `DESIGN.md` heading `## 1. Tokens`: replace with `## Colors`, `## Typography`, `## Layout`, `## Shapes`, keeping the prose about where tokens live in code. Drop the numeric prefixes.
- `DESIGN.md` heading `## 2. Components`: rename to `## Components`.
- `DESIGN.md` heading `## 3. Patterns and rules`: split into `## Overview`, `## Elevation & Depth` and `## Do's and Don'ts` as the content fits.
- `DESIGN.md` heading `## 4. Open questions`: remove; record anything undecided in the relevant section's prose.
- `DESIGN.md` section order: `Overview`, `Colors`, `Typography`, `Layout`, `Elevation & Depth`, `Shapes`, `Components`, `Do's and Don'ts`. Omit sections that do not apply; keep the rest in this order.
- Check with `npx @google/design.md@0.4.0 lint DESIGN.md` when Node is available.
